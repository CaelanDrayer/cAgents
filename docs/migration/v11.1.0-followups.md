## FU-1: Rewrite `scripts/ci/validate-agents.sh` for the archetype tree

**Why**: The current script iterates `{domain}/agents/{name}/SKILL.md`. After v11.1.0 those paths don't exist; the script will fail or report 0 agents. It is non-blocking because Vitest (`npm test`) is the actual runtime gate, but `npm run validate:agents` is broken until this is fixed.

**Files to change** (1 file, ≤5 file budget):
- `scripts/ci/validate-agents.sh`

**What to do**:

1. Replace the `DOMAINS` array (line ~54) with `ARCHETYPES`:
   ```bash
   ARCHETYPES=(developer operator advisor analyst creator writer strategist core leadership)
   ```

2. Replace the agent-discovery glob. Old pattern was `${PROJECT_ROOT}/${domain}/agents/*/SKILL.md`. New pattern walks each archetype tree:
   ```bash
   find "${PROJECT_ROOT}/${archetype}" -name SKILL.md
   ```
   (no `agents/` segment in the new tree — agents live directly under archetype/branch)

3. Replace the `domain:` frontmatter check (around line 179-189) with an `archetype:` check:
   - Required: `archetype:` field, value must match one of the 9 ARCHETYPES
   - Required for `developer`/`operator`/`advisor` only: `branch:` field, value must match the directory immediately above the agent's leaf dir
   - Forbidden: `domain:` field — emit ERROR if found (it was removed in v11.1.0)
   - Skip the branch check for 2-level archetypes (`analyst`, `creator`, `writer`, `strategist`) and flat roots (`core`, `leadership`)

4. Replace the `related-agents` lookup loop (around line 237-246). Current code searches `${check_domain}/agents/${related}/SKILL.md`. Replacement:
   ```bash
   # Search for related agent across the archetype tree
   if find "${PROJECT_ROOT}/${archetype}" -path "*/${related}/SKILL.md" -print -quit | grep -q .; then
     # found in any archetype
     :
   fi
   ```
   Iterate over all 9 ARCHETYPES until found.

5. Replace `validate_domain_overrides` (around line 402-426). The function reads `${domain}/config/domain_overrides.yaml` and validates `controller_catalog` agent paths exist on disk. The domain dirs (`engineering/`, `creative/`, etc.) still hold their `config/` files — only the `agents/` subdirs are gone — so the iteration still works. Update the path-existence check to use the new tree paths from `controller_catalog` (those configs were swept in v11.1.0 already).

6. Update header comment block (lines 1-30) to reflect the new structure: "Validates all agent SKILL.md files across all 9 archetype roots".

**Acceptance criteria**:
- `bash scripts/ci/validate-agents.sh` exits 0
- Reports 243 agents validated
- Reports 0 errors, ≤ existing baseline of WARNs (don't introduce new warnings)
- `npm run ci` passes (which runs `npm test && npm run validate:versions && npm run validate:agents`)
- `bash scripts/ci/validate-agents.sh --domain developer` works for single-archetype validation (rename the flag to `--archetype` if you prefer; document either way)

**Commit**: `fix(v11.1.1): validate-agents.sh — walk archetype tree`
