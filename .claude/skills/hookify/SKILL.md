# /hookify — Natural Language Hook Generator

Turn plain English into working Claude Code hooks.

## Examples

```
/hookify Warn me before I run any git push
/hookify Log every file I edit to a daily audit file
/hookify Block writes to the src/generated/ directory
/hookify Remind me of the current sprint goal before every bash command
/hookify Alert me when an agent is spawned with a description containing "prod"
```

## How to Handle a /hookify Request

### Step 1 — Parse the User's Intent

Identify from `$ARGUMENTS`:

1. **Trigger**: What event should fire the hook?
   - `before I run X` / `when I use X` → `PreToolUse` with matcher on tool name
   - `after I edit/write` → `PostToolUse` with matcher `Write|Edit`
   - `every time a file is saved` → `PostToolUse` with matcher `Write`
   - `when a subagent starts/stops` → `SubagentStart` / `SubagentStop`
   - `when I submit a prompt` → `UserPromptSubmit`
   - `when Claude stops` → `Stop`
   - `before compaction` → `PreCompact`

2. **Action**: What should the hook do?
   - `warn me` / `remind me` → return `systemMessage`
   - `block` / `prevent` / `deny` → return `deny: true` (PreToolUse only)
   - `log` / `record` / `audit` → append to a log file, return `null`
   - `alert me` → return `systemMessage`

3. **Condition**: Any filtering?
   - Tool matcher (e.g., `Bash`, `Write|Edit`, `Task`)
   - Content pattern (regex match on command / file path)

### Step 2 — Read Existing Files

Before generating anything:

1. Read `.claude/settings.json` to understand the current hook registrations
2. Read `.claude/hooks/hook-utils.cjs` (first 80 lines) to understand the `createHook()` API
3. Check `.claude/hooks/` for any existing hook with similar purpose (avoid duplicates)

### Step 3 — Choose a Hook File Name

Use kebab-case: `<action>-<trigger>.cjs`

Examples:
- `warn-git-push.cjs`
- `log-file-edits.cjs`
- `block-generated-writes.cjs`
- `sprint-goal-reminder.cjs`

If a very similar hook already exists, offer to extend it rather than create a new one.

### Step 4 — Generate the Hook File

Write `.claude/hooks/<name>.cjs` using this template:

```javascript
#!/usr/bin/env node
/**
 * <Hook Name> — <one-line description>
 * Generated by /hookify
 *
 * Event: <EventType>
 * Matcher: <matcher or "none">
 * Action: <warn|log|block>
 */

const fs = require('fs');
const path = require('path');
const { createHook, AGENT_MEMORY_DIR } = require('./hook-utils.cjs');

createHook('<HookName>', async (input) => {
  // Extract relevant input fields
  // e.g. const command = input.tool_input?.command || '';

  // --- CONDITION CHECK ---
  // If the condition does not match, return null immediately (pass-through)
  // e.g. if (!command.includes('git push')) return null;

  // --- ACTION ---

  // WARN: inject a system message
  // return { continue: true, systemMessage: 'Warning: ...' };

  // BLOCK (PreToolUse only):
  // return { deny: true, reason: 'Blocked because ...' };

  // LOG: write to file, then pass through
  // fs.appendFileSync(logFile, JSON.stringify(entry) + '\n');
  // return null;
});
```

**Rules for the generated hook:**

- Use only built-in Node.js modules (`fs`, `path`, `os`) — no npm packages
- Always import `createHook` from `./hook-utils.cjs`
- Return `null` for pass-through (non-blocking)
- Return `{ deny: true, reason: '...' }` to block (PreToolUse only)
- Return `{ continue: true, systemMessage: '...' }` to warn
- Write logs to `Agent_Memory/_system/logs/` (use `AGENT_MEMORY_DIR`)
- Keep the handler under 50 lines; single responsibility

### Step 5 — Register in settings.json

Edit `.claude/settings.json` to add the new hook under the correct event type.

**Template for an event with no existing hooks:**
```json
"<EventType>": [
  {
    "hooks": [
      {
        "type": "command",
        "command": "bash -c 'R=\"${CLAUDE_PLUGIN_ROOT:-${CLAUDE_PROJECT_DIR:-$(pwd)}}\"; node \"$R/.claude/hooks/run-hook.cjs\" <hook-name-without-cjs>'",
        "timeout": 5
      }
    ]
  }
]
```

**Template for PreToolUse with a matcher:**
```json
{
  "matcher": "<ToolName>",
  "hooks": [
    {
      "type": "command",
      "command": "bash -c 'R=\"${CLAUDE_PLUGIN_ROOT:-${CLAUDE_PROJECT_DIR:-$(pwd)}}\"; node \"$R/.claude/hooks/run-hook.cjs\" <hook-name>'",
      "timeout": 5
    }
  ]
}
```

Add `"async": true` for logging-only hooks so they do not slow down tool execution.

### Step 6 — Confirm to the User

After writing the file and updating settings.json, show the user:

1. The hook file path created
2. The event type and matcher it is registered under
3. A one-line summary of what it will do
4. How to test it: `echo '{"tool_input": {"command": "..."}}' | node .claude/hooks/<name>.cjs`

### Step 7 — Test the Hook (Optional)

If the user asks to test, run:

```bash
echo '<minimal JSON matching the event>' | node .claude/hooks/<name>.cjs
```

Verify it produces valid JSON output (`{"continue": true}` or a deny response).

## Supported Events Reference

| User Says | Event Type | Notes |
|-----------|-----------|-------|
| before/when using a tool | `PreToolUse` | Add `matcher` for specific tool |
| after using a tool | `PostToolUse` | Add `matcher` for specific tool |
| when I submit a prompt | `UserPromptSubmit` | No matcher needed |
| when Claude stops | `Stop` | Can block with `decision: "block"` |
| when a subagent starts | `SubagentStart` | Cannot block |
| when a subagent finishes | `SubagentStop` | Cannot block |
| before compaction | `PreCompact` | Cannot block |
| when a task completes | `TaskCompleted` | Can return `continue: false` |
| when a teammate is idle | `TeammateIdle` | Can return `continue: false` |
| when permission is requested | `PermissionRequest` | Can auto-approve or deny |

## Limitations

- Hooks run as Node.js CJS scripts — no async npm packages, no ES modules
- `PreToolUse` is the only event that can block tool execution
- `Stop` can block Claude from stopping (use sparingly)
- Log files should be in `Agent_Memory/` which is git-ignored
- Hooks must execute in under 5 seconds (default timeout)
